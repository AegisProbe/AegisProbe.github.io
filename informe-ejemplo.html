1. Resumen ejecutivo

Durante la evaluación se revisaron los módulos de autenticación, administración, API pública y configuración de cabeceras de seguridad. Se identificaron riesgos que podrían afectar la confidencialidad de información sensible y la integridad de operaciones internas.

2. Alcance evaluado

El alcance definido por el cliente incluyó una aplicación web pública, un panel administrativo y una API REST de pruebas. La revisión se realizó con credenciales de usuario estándar y acceso parcial a documentación funcional.

  • Aplicación web principal: autenticación, sesión, formularios y roles.
  • API REST: autorización, validación de entradas y exposición de datos.
  • Configuración de seguridad: cabeceras HTTP, errores y controles básicos.

3. Hallazgo destacado

SEVERIDAD ALTA

Control de acceso insuficiente en panel administrativo

Se detectó que un usuario con privilegios limitados podía consultar una ruta administrativa modificando manualmente el identificador de recurso en la URL.

Impacto potencial

Un atacante autenticado podría visualizar información no autorizada, alterar registros internos o recopilar datos para ataques posteriores.

Recomendación

Validar permisos en el servidor para cada recurso, aplicar controles por rol y registrar intentos de acceso no autorizado.

4. Plan de corrección sugerido

Prioridad Acción recomendada Responsable sugerido Plazo
Alta Corregir validación de permisos en rutas administrativas. Equipo Backend 1 a 3 días
Media Agregar pruebas automatizadas de autorización por rol. QA / Desarrollo 1 semana
Baja Mejorar mensajes de error y documentación interna. TI / Seguridad 2 semanas

5. Conclusión

El entorno evaluado presenta una base funcional correcta, pero requiere reforzar controles de autorización, validación de entradas y seguimiento posterior mediante re-test. AegisProbe recomienda corregir primero los hallazgos críticos y altos, luego verificar su mitigación.
