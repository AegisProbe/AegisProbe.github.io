Tipos de evaluación

Elegimos el enfoque según el nivel de información disponible, el objetivo del cliente y el tipo de riesgo que se desea comprobar.

Black Box

Prueba sin información previa, simulando la perspectiva de un atacante externo que intenta descubrir servicios, tecnologías y puntos débiles desde cero.

  • Ideal para medir exposición pública.
  • Incluye reconocimiento, enumeración y validación controlada.
  • Permite conocer qué podría encontrar un atacante real.

Grey Box

Evaluación con información parcial, como usuarios de prueba, diagramas generales o alcances definidos. Combina velocidad, realismo y profundidad técnica.

  • Útil para aplicaciones con roles de usuario.
  • Permite revisar autenticación, permisos y flujos críticos.
  • Reduce tiempos sin perder contexto de seguridad.

White Box

Prueba con acceso completo a documentación, arquitectura, configuraciones o código fuente para realizar un análisis profundo y orientado a corrección.

  • Recomendado para auditorías internas o preproducción.
  • Facilita encontrar errores lógicos y malas prácticas.
  • Entrega recomendaciones precisas para desarrollo y TI.

Cómo trabajamos

Seguimos una metodología ordenada para identificar, comprobar, documentar y corregir riesgos de seguridad.

1

Reconocimiento

Recolectamos información inicial sobre el objetivo autorizado.

2

Escaneo

Identificamos servicios, tecnologías y posibles puntos débiles.

3

Explotación controlada

Validamos vulnerabilidades de forma segura y documentada.

4

Post-explotación

Medimos el posible impacto real de los hallazgos encontrados.

5

Reporte

Entregamos un informe técnico y ejecutivo con recomendaciones.

6

Re-test

Verificamos que las vulnerabilidades hayan sido corregidas.
